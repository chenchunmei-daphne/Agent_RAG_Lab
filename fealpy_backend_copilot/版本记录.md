# FEALPy Backend Copilot 版本记录

本文记录各版本的目标、实现范围、评测结果及迭代原因。评测中的 Recall@K 表示：目标接口是否出现在检索结果前 K 个候选中；Answer Accuracy 表示最终首选接口是否与标注接口一致。

## v01：接口事实库与端到端问答原型

### 完成功能

- 从 FEALPy `backend` 的 NumPy、PyTorch 后端整理出 220 条 `bm.*` 接口记录，形成以“接口”为中心的 `all_interfaces.json`。
- 每条记录尽量保存接口名称、签名、参数、源码位置、NumPy/PyTorch 映射及说明等事实信息。
- 使用 BGE-M3 将接口文本向量化，并使用 Chroma 建立持久化向量数据库。
- 实现“用户问题 → 意图解析 → 向量检索与规则重排 → Qwen/模板回答”的问答链路；回答原本尝试给出接口、参数、后端映射和示例代码。
- 实现 FastAPI、Gradio、会话隔离、LLM 结构化意图输出、答案中的 API 名称校验及失败时的规则/模板回退。
- 建立 55 条内部测试题，提供 Recall@K、Answer Accuracy 及失败样例导出。

### 评测结果

使用 55 题内部基准、Top K=5、`hybrid` 模式评测：

| 指标 | 结果 |
|---|---:|
| Recall@1 | 34.55%（19/55） |
| Recall@5 | 43.64%（24/55） |
| Answer Accuracy | 34.55%（19/55） |

失败中有 31 题属于 Top-5 未召回，5 题属于“正确接口已召回但最终答案首选错误”。说明主要瓶颈在检索和候选排序，而不只是回答生成。

### 当前结论

v01 完成了从数据、向量库、检索、LLM 到服务界面的完整原型，为后续分析提供了可运行的基线。本版本不在此之前设置迭代前因。

## v02：以“计算能力”为中心的接口检索 MVP

### 为什么迭代

v01 的记录单元是接口，面向检索的描述较多来自“函数名 + 通用分类”的模板，和用户以自然语言表达的计算目标存在距离；同一计算能力的别名、易混淆接口之间也缺少显式关系。评测结果表明，直接丰富参数、示例或后端细节，无法优先解决“能否找到正确接口”的核心问题。

因此 v02 先收缩目标：只解决“用户想完成什么计算功能 → 推荐正确的 `bm.*` 接口”，暂不承诺完整的参数说明、可运行示例、NumPy/PyTorch 差异解释或多接口比较问答。找到接口后，用户可通过代码补全和源码注释继续了解用法。

### 完成功能

- 重构数据为两层实体：
  - **接口事实（interface）**：保存真实 `bm.*` 接口及其源码等可核验事实；
  - **计算能力（capability）**：保存用户意图、自然语言表达、目标接口、别名和易混淆接口的差异说明。
- 经源码审计，将覆盖范围从 220 个接口补全至 233 个接口；合并等价别名后形成 218 条能力记录和 40 组接口对比关系。
- 嵌入文本以能力的正向信息为主，避免把“不是该接口”的对比文本混入向量语义；检索命中能力后再展开为主推荐接口和备选接口。
- 取消分类/意图的硬过滤，改为软加权，减少错误分类导致正确候选被提前排除的问题。
- 构建新的 Chroma 向量库 `vector_store/vector_store_v02/chroma`，Collection 为 `fealpy_capabilities_v02`，共 218 条、1024 维归一化向量。
- 将检索器、规则回答、评测脚本、FastAPI、Gradio 和兼容入口切换至 v02 数据库；仍保留 Qwen 调用、事实校验和失败回退等工程能力。
- 增加模型列表、用户选择模型与额度/服务不可用时的自动切换机制，自动选择时优先尝试 `qwen3.7`、`deepseek-v4` 系列。

### 评测结果

使用与 v01 相同的 55 题内部基准、Top K=5、`rule` 模式评测。选择规则模式是为了隔离外部模型服务状态，仅评价 v02 的能力检索与确定性 Top-1 推荐；因此该次 Answer Accuracy 与 Recall@1 数值相同。

| 指标 | v01 | v02 |
|---|---:|---:|
| Recall@1 | 34.55%（19/55） | 83.64%（46/55） |
| Recall@2 | 40.00% | 90.91% |
| Recall@3 | 43.64% | 92.73% |
| Recall@4 | 43.64% | 96.36% |
| Recall@5 | 43.64%（24/55） | 98.18%（54/55） |
| Answer Accuracy | 34.55%（19/55） | 83.64%（46/55） |

v02 剩余 9 题失败中，1 题的目标接口没有进入 Top-5，8 题已经召回正确接口但没有排到第一；没有 pipeline error。结果说明数据建模调整显著改善了“找到正确接口”的能力，但候选排序仍有优化空间。

### 当前边界与下一步

- 当前系统的稳定能力是接口定位与候选推荐，不应将其描述为已稳定支持参数教学、后端 API 对照、示例代码生成或接口差异比较。
- 55 题为内部测试集，适合做版本横向比较；后续应补充独立留出集，避免数据构建与评测问题重合造成指标偏高。
- 后续迭代可在保持 capability 检索结构的基础上，逐步补齐高频接口的参数、后端映射、代码样例和对比问答数据，并针对当前 Top-1 排序失败样本进行定向优化。
